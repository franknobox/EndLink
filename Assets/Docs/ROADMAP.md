# EndLink Roadmap

EndLink 是一个早期 3D 连携战斗 demo，目标参考类似《异度之刃》和《明日方舟：终末地》的小队协同战斗体验。当前阶段仍处在白模验证期，优先建立单人控制、镜头、状态机和战斗基础能力，再逐步扩展到连携与小队表现。

文档更新原则：不变动结构，实际开发与计划有冲突则调整文档表述。
开发规划：有新增就新增，做完了就去掉，表述简洁。

## 后续开发规划

### 1. 单人行动基底
内容：基本完成

### 2. 连携战斗基底
内容：基础建设完成，具体规则有待设计。

### 3. 基础的队伍管理
内容：基本完成

### 4. 敌人基础制作

内容：后续接入战斗执行和行为树以及其他正式AI逻辑；一个敌人可以主动接近并攻击我方，死亡后能从目标系统和助战流程中稳定移除。

### 5. 连携触发与四类 Action Base 版

内容：连携触发规则初版；连携释放初版，按反应目标、软锁目标和目标失效规则解析攻击目标；四类 Action Base 版

目标是在敌人可用于稳定测试后，做出第一版可验证的连携规则闭环：完整的“触发连携 -> 执行反应 -> 观察结果”流程。

### 6. 战斗系统整体基础建设

- 角色数值系统已建立轻量 `CharacterStats` ；伤害结算管线已建立基础，后续持续优化完善；已建立独立标准化 `CombatTarget`。
- Action 执行统一接口：`ICombatActionExecutor` 提供 `CanExecute`、`TryExecute`、冷却查询和目标传入。
- 受击规则已完成初版；硬直、打断、击飞、死亡后碰撞处理边界后续再设计。

### 7. 战斗 UI 第一版

目标是在已有玩家、队友、敌人和战斗动作基础上，补齐最小可读的战斗界面。

计划内容：
- 主控战斗 UI：显示主控生命值、当前主动技能冷却、连携请求槽位和极限技能量预留位置。
- 队友战斗 UI：显示两个队友的主动技能冷却、连携请求槽位和基础状态提示。
- 目标 UI：显示当前自动软锁目标的基础信息，例如敌人血量、目标点状态和后续可扩展的弱点/标签提示。
- 冷却反馈：复用并扩展 `UICombatActionSlot`，让技能槽、连携槽和后续大招槽统一读取动作与冷却来源。
- 连携预备 UI：先做占位显示，后续等连携规则落地后接入可释放、高亮和窗口倒计时。

阶段完成标准：
- 不看 Console 也能判断主控和队友技能是否可用。
- 自动软锁到敌人后能在 UI 上看到目标基础状态。
- UI 结构可以继续承接后续连携窗口、大招能量和队友状态显示。

### 10. 角色定义、成长与存档基础

目标是在战斗演示闭环稳定后，把角色的静态配置、成长进度和跨场景保存逐步拆清楚。

计划内容：
- 先建立稳定角色 ID 思维，主控、队友和后续可培养角色都通过 ID 识别，不依赖场景物体名。
- 战斗演示可玩后，建立 `CharacterDefinition`，用于保存角色基础属性、默认技能、Prefab、图标和静态配置。
- 开始做轻 RPG 成长时，再建立 `CharacterProgressData`、`GameSaveData` 和 `SaveManager`，保存等级、经验、技能点、加点、技能解锁和队友培养状态。
- 多场景流程开始后，再建立运行时全局上下文，让队伍和角色进度不依赖单个场景里的物体。

阶段原则：
- `CharacterStats` 只负责运行时数值入口，不直接负责永久保存。
- `ScriptableObject` 作为设计配置，不直接当作玩家存档修改。
- 正式存档优先使用结构化数据和本地文件，复杂角色进度不使用 `PlayerPrefs`。
