# EndLink Roadmap

EndLink 是一个早期 3D 连携战斗 demo，目标参考类似《异度之刃》和《明日方舟：终末地》的小队协同战斗体验。当前阶段仍处在白模验证期，优先建立单人控制、镜头、状态机和战斗基础能力，再逐步扩展到连携与小队表现。
目前优先做好单人ARPG/ACT体验，参考《尼尔：机械纪元》、《无限机兵》、《只狼》及其他魂类游戏。

文档更新原则：不变动结构，实际开发与计划有冲突则调整文档表述。
开发规划：有新增就新增，做完了就去掉，表述简洁。


## 近期 Review 反馈


### 主要发现

- **P0：EndLink 特色战斗链路实际上不可达。** `Hitbox` 还会在受击结算前广播命中，并在结算后无条件附加标签，导致格挡或弹反后仍可能触发命中事件和标签反应。
- **P0：ACT 命中表现接近空白。** 当前尚未形成 Hitstop、Cinemachine Impulse、手柄震动、音效和 VFX 等通用反馈链路，玩家正式动画与视觉资源也未完整接入。即使伤害和判定正确，轻重攻击、格挡、弹反、反应与奥义之间仍缺少可感知差异。
- **P0：玩家有状态机，但动作深度不足。** 三段普攻尚未形成三个有差异的正式动作，攻击状态主要只处理下一段普攻缓存；普攻、技能、闪避和格挡之间缺少取消与优先级关系。硬锁还不能切换目标，双视角模式也尚未包含锁定横移和定向闪避。
- **P1：敌人目前只有一种压力模型。** 实战敌人仍以地面近战为主，虽然已有追击、跳劈、连击、围攻协调和软站位，但还没有远程压制、浮空单位、精英或 Boss、阶段变化、韧性失衡、霸体窗口和清晰预警。当前更缺第二种战斗角色和可收尾的精英战，而不是继续扩展 AI 架构。
- **P1：ARPG 与公开 Demo 配套基本为空。** 当前没有装备、掉落、成长、构筑选择与存档，也缺少暂停、设置、按键重绑定、教学和目标提示。完整背包暂时不是必要项，但至少需要一次有感知的轻量构筑选择；队友 Link Down 也仍缺少玩家救助与重新接入流程。
- **P1：自动化保障明显不足。** 现有测试覆盖与运行时代码规模不匹配，连段、动作取消、格挡结算、标签反应、连携窗口和协同率等关键边界尚未形成稳定回归保护。

### 程序可先行

- 命中结果与拦截语义、标签反应最小执行链，以及协同率和奥义效果接口。
- 通用战斗反馈调度基础已建立；之后为实际 Action 配置反馈资产。
- 玩家动作取消策略、硬锁目标切换、锁定移动与定向闪避，不依赖最终动画资源，已完成逻辑骨架。
- 敌人韧性、失衡、攻击预警和远程攻击执行基础，不需要先扩展行为树。
- 对稳定纯逻辑边界补充 EditMode 测试，并在关键场景流程稳定后增加少量 PlayMode 冒烟测试。

- 当前继续保留 Fast Action 与 SoulsLike 双预设实验，在手感方向确定前不引入强绑定某一种模式的大型系统。



## 后续开发规划


### 11. 编辑器工具优化

内容：
- 整理并优化现有战斗数据创建、调试监视和 HUD 生成工具，统一基础交互、状态提示、资源定位和错误反馈。
- 增加场景配置体检，集中检查缺失引用、重复组件、Layer、NavMesh、战斗数据和常见接线问题，并支持快速定位与安全修复。
- 建立场景联调窗口，按玩家、镜头、战斗和敌人分类集中调整高频参数，并标明参数的真实来源组件。
- 支持 Play Mode 参数差异记录，在退出播放后选择性将白名单配置应用回场景，不保存运行时状态或第二套数据。
- 增加 Action 与动画校准能力，检查动画事件和动作时序，并在 Scene View 显示 Hitbox、攻击范围与位移信息。
- 为战斗数据工具补充批量校验、重复 ID 检查、缺失资源检查、筛选、复制和引用定位。
- 增加 Playtest 快捷控制，用于恢复生命、清除冷却与标签、调整协同率、重置敌人和返回出生点。



### 12. 动画与游戏表现衔接优化

计划内容：
- 动画播放基础：统一 Avatar、Root Motion、原地动画、循环姿势、状态切换和播放速度配置，解决模型漂移、回弹、浮空、脚滑和错误循环。
- 逻辑与空间对齐：校准角色逻辑根、视觉模型、角色控制器、锁定点、Hitbox、地面高度和攻击朝向，避免动画位置与碰撞体脱节。
- 动作时序对齐：按动画关键帧调校 `startup / active / recovery` 对应实际动作；稳定后再逐步接入动画事件驱动判定窗口。
- 动作节奏调校：调整动画速度、过渡时间、攻击冷却、移动速度、攻击位移、追踪、击退和硬直时间，使表现连贯清晰。
- 攻击可读性：强化敌人出手前的预备动作、攻击方向、技能差异、危险范围和命中反馈，避免重要动作表现不明显。
- 打击表现补充：逐步加入短暂卡肉、Cinemachine 镜头冲击、手柄震动、材质闪烁、武器/肢体拖尾、命中特效、落地冲击、音效和必要的屏幕反馈。
- 联调与验证：先完成 APS01 敌人的完整动画战斗闭环，再检查不同帧率、坡地、转向、受击打断和围攻情况下的稳定性。

阶段原则：
- 当前仍以数据时序驱动战斗判定，动画事件在动作资源和流程稳定后逐步接管关键时点。
- 卡肉、镜头冲击、手柄震动、材质反馈和基础 VFX 不依赖最终动画 Clip，可以提前搭建轻量可调的通用接口。


### 13. 单人向战斗 UI 与键位确定

内容：
- 按单人 ARPG / ACT 战斗方向整理 HUD 信息层级，明确生命、动作技能、冷却、锁定、防御反馈和奥义等必要显示。
- 确定键鼠与手柄的默认键位，解决攻击、技能、闪避、冲刺、格挡、交互、锁定和奥义之间的输入冲突。
- UI 统一读取 Input System 的实际绑定并显示对应键位，避免界面文本与运行时配置不一致。
