# EndLink Roadmap

EndLink 是一个早期 3D 连携战斗 demo，目标参考类似《异度之刃》和《明日方舟：终末地》的小队协同战斗体验。当前阶段仍处在白模验证期，优先建立单人控制、镜头、状态机和战斗基础能力，再逐步扩展到连携与小队表现。
目前优先做好单人ARPG/ACT体验，参考《尼尔：机械纪元》、《无限机兵》及其他魂类游戏。

文档更新原则：不变动结构，实际开发与计划有冲突则调整文档表述。
开发规划：有新增就新增，做完了就去掉，表述简洁。

## 后续开发规划

### 7. 战斗 UI 第一版

内容：
- UGUI 生成通道：通过Editor工具生成HUD。主控状态、主动技能、调试信息、奥义、队友头像（连携窗口）;刷新方式
- 敌人UI：先做头顶血条、目标点和基础状态提示，后续扩展标签、弱点、精英/首领标识和更多战斗反馈。

### 8. 白模箱庭地图

内容：
- 建立初版白盒测试场地。包含基础地形、高低差、坡道、障碍、开阔战斗区、窄通道、敌人摆放点、出生点和简单路径验证。
- 制作基础世界/关卡交互组件，覆盖玩家交互检测以及门、电梯、机关等灰盒交互对象，建立可复用的触发、启用和反馈流程。
- 碰撞矩阵


### 9. 敌人 AI 与基础敌人规格

内容：
- 已明确敌人战斗规格。自然的敌人战斗行为轻量状态机，后续可升级为行为树。建立多敌人围攻限制和表现。

- 先完成地面近战敌人的最小 AI 闭环，再扩展地面远程和游离态浮空单位。再回头优化队友战斗逻辑。

### 10. 主控角色 ARPG / ACT 向优化

已完成内容：攻击缓冲、攻击期间软锁转向、受击击退优化、优化闪避速度曲线、优化摄像机缩放。
后续：
- 动画驱动动作：接入动画事件，让动作与角色动画同步。真正接入 Animator 参数、补齐动作锁定与打断规则
- 普攻连段与派生：建立基础连段、输入缓冲、连招分支、取消窗口和动作优先级。
- 防御交互循环：以格挡弹反为主角核心防御方式，建立防御方向、弹反窗口、格挡结果和敌人失衡反馈；闪避作为辅助防御手段。
- 攻击位移与追踪：加入近战踏步、有限攻击吸附、转向辅助和目标移动追踪，减少攻击原地挥空。

### 11. 编辑器工具优化

内容：
- 整理并优化现有战斗数据创建、调试监视和 HUD 生成工具，统一基础交互、状态提示、资源定位和错误反馈。
- 建立统一的 Editor Window，集中调整当前场景中需要反复联调的组件参数；具体参数分类后续根据实际使用频率确定。
- 工具直接读写场景组件的真实序列化字段，不保存第二套重复数据；支持 Undo、场景脏标记和快速定位原组件。
- 支持 Play Mode 中实时调参，并通过明确的“记录运行时值 / 应用到场景”流程，在退出播放后保存选定参数，避免自动覆盖场景数据。
- 第一版只服务当前场景实例，不处理跨场景预设、批量 Prefab 修改或独立配置资产。

### 12. 角色定义、成长与存档基础

目标是在战斗演示闭环稳定后，把角色的静态配置、成长进度和跨场景保存逐步拆清楚。
计划内容：
- 先建立稳定角色 ID 思维，主控、队友和后续可培养角色都通过 ID 识别，不依赖场景物体名。
- 战斗演示可玩后，建立 `CharacterDefinition`，用于保存角色基础属性、默认技能、Prefab、图标和静态配置。
- 开始做轻 RPG 成长时，再建立 `CharacterProgressData`、`GameSaveData` 和 `SaveManager`，保存等级、经验、技能点、加点、技能解锁和队友培养状态。
- 多场景流程开始后，再建立运行时全局上下文，让队伍和角色进度不依赖单个场景里的物体。

阶段原则：
- `CharacterStats` 只负责运行时数值入口，不直接负责永久保存。
- `ScriptableObject` 作为设计配置，不直接当作玩家存档修改。
- 正式存档优先使用结构化数据和本地文件，复杂角色进度不使用 `PlayerPrefs`。
