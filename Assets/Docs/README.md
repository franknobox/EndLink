# EndLink Docs

本目录用于保存 EndLink 工程内的开发文档。

## 文档分类

| 文档 | 用途 |
|---|---|
| `ROADMAP.md` | 后续开发路线和阶段目标。 |
| `FEATURES.md` | 当前已经完成的工程功能索引，只保留概览、状态表和跳转入口。 |
| `ART.md` | 美术资源目录、命名、分支接入和资源协作规则。 |
| `Features/` | Feature 详情子文档，按模块拆分，避免 `FEATURES.md` 无限膨胀。 |
| `ISSUE.md` | 已知问题、技术债、设计债和需要后续回看的事项。 |
| `Design/` | 面向程序开发使用的策划文档，记录会影响系统实现、数据结构、玩法规则和表现需求的设计结论。 |

## Feature 文档

| 文档 | 用途 |
|---|---|
| `Features/PLAYER.md` | 玩家、3C、玩家状态机和玩家侧战斗接线。 |
| `Features/COMBAT.md` | 战斗数据、目标、伤害、受击、Hitbox、标签和事件系统。 |
| `Features/PARTY.md` | 小队管理、小队战斗上下文和连携窗口。 |
| `Features/ALLY.md` | 队友状态机、助战和跟随表现。 |
| `Features/ENEMIES.md` | 敌人身份与生命目标、敌人感知与大状态机、敌人移动与战斗能力。 |
| `Features/UI.md` | 运行时 HUD、动作槽位和通用 UI 组件。 |
| `Features/TOOLS.md` | Editor 工具、数据创建工具和调试监视窗口。 |

## Design 文档

| 文档 | 用途 |
|---|---|
| `Design/世界观设定.md` | 记录背景概要、核心概念、世界观术语，以及这些概念对角色、战斗、UI 和视觉方向的约束。 |
| `Design/战斗设计.md` | 记录战斗体验目标、动作类型、标签反应、连携规则、目标锁定和敌人战斗定位。 |

## ART 文档

`ART.md` 用于记录美术资源进入工程时需要遵守的规则，包括 `Assets/Art` 的定位、资源命名、逻辑 Prefab 与视觉 Prefab 的边界、锁文件策略、导入规则预留、`art` 分支接入流程，以及未来 Addressables 和自动预览的方向。

## 维护原则

- 策划文档以“当前工程需要执行的结论”为主，不追求一次性写完整世界观。
- 飞书导入内容进入 `Design/` 时，先完整保留原文内容，再在后续小标题下补充工程实现需要的规则和结论。
- 美术资源目录、命名和分支接入规则更新时，同步维护 `ART.md`。
- 新增或修改工程功能后，先更新 `FEATURES.md` 的状态索引，再更新对应的 `Features/` 子文档详情。
- `FEATURES.md` 不记录演变历史和长篇配置说明；历史、技术债和待回看问题分别进入 `ISSUE.md`。
- 发现技术债、设计债或容易反复踩的问题时，同步记录到 `ISSUE.md`。
- 玩法概念如果会影响脚本、ScriptableObject、Prefab、UI 或调试工具，需要写进 `Design/`。
